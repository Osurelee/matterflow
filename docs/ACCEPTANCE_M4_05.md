# M4-05 图片与文件附件验收

日期：2026-10-13；状态：已完成（M4功能范围；目标设备/跨设备实测归M7）。依据PRD v0.6.2第8.1/8.4节、技术设计第6节与AT-32。

## 实际交付

- 新增迁移 `0005_m4_media`、`assets` 与 `task_asset_links` schema；不修改已应用的旧迁移。附件的正文引用受守卫保护：仍被正文引用时拒绝移除，先改正文并保存；移除附件软关联但保留文件和历史事件。
- 私有媒体服务：签名/编码/大小校验（图片10MiB、PDF/UTF-8 txt/Markdown 20MiB；录音接入另属M4-06）、随机存储键、SHA-256、稳定上传requestId去重；文件权限0600、媒体目录0700，不在public目录。
- 新接口：`POST /api/uploads`；`GET|POST /api/tasks/:id/attachments`；`DELETE /api/tasks/:id/attachments/:linkId`；`GET /api/assets/:id/content`。读取要求登录、owner与当前有效关联；图片可内联/放大，普通文件使用附件下载；成功上传但未关联的资产不开放读取。
- 详情页接入附件区：图片选择/设备相机入口（capture属性并保留通用文件选择退路）、PDF/文本/Markdown选择、拖放和剪贴板图片、逐项本机缩略预览、上传进度、失败重试、成功后附件展示/下载/移除。未上传预览状态明确；未提交附件阻止关闭/刷新时静默丢失。
- 正文图片需由用户显式点击“插入正文”；可视编辑器在光标位置插入私有asset令牌并显示内联图，源模式按选区插入；普通上传不会修改正文。正文仍引用图片时，移除附件会给冲突提示避免留下坏引用。
- 事项版本随附件挂载/移除递增；状态事件留摘要；已归档事项拒绝挂载/移除。

## 验证

- `npm run typecheck`：通过。
- `npm run test:m4`：通过；包括生产构建、M4正文/草稿/清单契约、媒体token安全渲染测试，以及隔离M1集成进程中的真实HTTP媒体闭环。

- `npm run db:migrate` 在空隔离数据库成功应用0000～0005，`integrity_check=ok`、schema_version=6；Drizzle schema检查通过。正式库未迁移。

## 边界与后续

- 没有目标手机/桌面实机或公网验收；浏览器对capture相机菜单的具体呈现、移动触控/粘贴行为、真实网络中断与跨设备附件读取需M7验证。失败时保留所选文件用于重试，但关闭页面后未上传二进制不会作为服务器草稿恢复。
- 无关联上传资产目前留在私有媒体目录；技术设计允许24小时后清理，本轮未交付定时清理。M8全量备份/恢复仍需覆盖数据库与二进制，不能据此宣称媒体备份闭环。
- 录音的页面内MediaRecorder流程、捕获/进展媒体关联属于M4-06；多媒体快速捕获属于M4-07；音频真实格式/跨设备播放属于M4-06/M7。
- 本项状态：已完成（M4代码与隔离验收）；不代表AT-32中明确归属M7的设备/网络/播放项全部完成。
