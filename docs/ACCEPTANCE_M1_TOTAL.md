## 2. 待修复问题

### M1-A01 · P1 · 恢复后复活已撤销的旧会话（M1-06）

位置：scripts/restore.mjs:25–35。恢复复制sessions与原auth_version后只做只读校验，没有撤销会话；运行手册也未要求在启用恢复库前执行必需的撤销步骤。

复现：登录得到会话 → 备份 → 原库改密，原会话返回401 → 恢复该备份并启动隔离应用 → 同一个旧会话调用/auth/me返回200。恢复库中仍有1条旧会话。技术设计第9节明确要求撤销恢复库中的旧会话。

修复验收：恢复后、可投入运行前删除旧sessions，并明确auth_version策略；撤销动作在生成恢复件最终checksum之前执行，不能只在文档中建议可选操作。旧会话必须401，恢复账号凭据重新登录成功，数据及事件保持正确。备份本身按时间点恢复密码属于快照语义，应在手册说明，不将其与会话复活混为一谈。

### M1-A02 · P2 · 合法密码能设置却不能登录（M1-03/04）

位置：src/app/api/auth/login/route.ts:21。初始化/改密按Unicode码点限制12–128，登录用JavaScript string.length（UTF-16代码单元）限制128。

复现：在隔离账号将密码修改为80个emoji，改密返回200；随后用相同密码登录返回401。80个码点在设计允许范围内，却有160个UTF-16代码单元。用户可能退出后无法登录，需要本机重置。

修复验收：所有密码入口遵循同一码点口径，保留输入不trim。加入至少80个非BMP字符的初始化/改密/登录往返，以及128和129码点边界。

### M1-A03 · P2 · 更新接口允许改写已归档事项（M1-05）

位置：src/server/services/mutations.ts:60–63。标题更新仅检查owner和deleted_at，没有检查事项archived_at或所属空间/项目归档状态。

复现：创建事项，在隔离库构造合法done并归档的状态，调用PATCH且expectedVersion正确，返回200并改变标题。PRD第5.4节要求已归档事项只读。这个接口已经公开具备写能力，不能因归档UI尚未开发就省略服务端约束。

修复验收：在同一事务内检查事项与容器归档状态；新请求写归档事项返回409，标题/version/事件/幂等记录不变。未归档正常编辑仍成功；有效历史幂等重放保留既定语义，不重复写入。

### M1-A04 · P2 · 开发/生产目录配置问题尚未关闭（M1-01/02）

位置：scripts/lib/env.mjs:35–36、drizzle.config.ts、package.json数据库命令。加载器仍固定`loadEnvConfig(dir,false)`，数据库命令固定production，缺少与next dev对应的显式开发模式。

上一轮已复现.env.development与.env.production分别设目录时，脚本读prod、next dev读dev；本轮确认相关实现未变。现有环境测试覆盖解析语法，但没有覆盖两种运行模式一致性。验收条件仍见[第三轮报告](ACCEPTANCE_M1_RECHECK_3.md)：提供明确模式选择，在dev/prod分别迁移、初始化、启动，确认各自同库且互不污染。
