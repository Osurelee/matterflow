# M2-04 事项安排与执行字段验收

状态：服务端、详情页及隔离回归通过。验证命令：`npm run test:m2`（生产构建 + 隔离 API 集成套件）。未操作正式数据库或公网入口。

## 交付

- 新增 `PATCH /api/tasks/:id/planning`：在一个版本化幂等请求中保存优先级、计划日期、截止日期、下次跟进日期、下一步动作和阻塞原因。
- 详情 API 返回上述持久化字段；详情页提供优先级、三个日期、下一步与阻塞原因编辑，失败时保留输入。
- 服务端只接受 `none/low/medium/high` 优先级；日期严格要求有效 `YYYY-MM-DD` 日历值（拒绝2月30日等）；允许过去日期。
- 计划日期晚于截止日期返回400并拒绝；跟进日期晚于截止日期允许保存，界面显示风险提示。
- 下一步动作最多500码点、阻塞原因最多1000码点，拒绝超限。
- 结束事项禁止新增跟进日期（返回409）；计划/截止等字段按现行规则保存。变更在单一事务中更新 version、追加 `task_updated` 事件并记幂等请求。
- 详情关闭时若标题、安排字段或状态/原因尚未保存，会提示确认。

## 验证

- `npm run typecheck` 通过。
- `npm run test:m2` 通过，覆盖无效日历日、计划晚于截止、长度超限、有效字段持久化、跟进晚于截止允许、幂等重放无重复版本变化，以及结束事项不能加跟进日期。
