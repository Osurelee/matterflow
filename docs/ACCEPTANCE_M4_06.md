# M4-06 页面录音进度记录

日期：2026-10-13；状态：进行中（页面代码及隔离服务器链路已实现，真实录音设备验收待执行）。依据PRD v0.6.2第8.2～8.3节、FR-19/20、AT-34与技术设计第6～7节。

## 已实现

- 统一 `AudioRecorder` 页面组件，可在事项详情、快速新增捕获、追加进展三个位置直接录音；首个明确操作才申请麦克风。支持权限/安全上下文降级、浏览器MediaRecorder候选MIME探测、录音指示/计时/停止收尾、5分钟与24MiB限制、试听、重录、继续录下一段、放弃、切后台/音轨中断处理及麦克风释放。
- 未提交片段在本机试听；录音上传有进度/取消，失败保留本机片段可重试。staging资产在捕获/进展保存前不显示为服务器已关联；快速捕获可以只靠录音生成临时标题并原子创建事项+附件。
- 事项详情录音直接关联Task；追加进展可纯录音或文字加录音，进展事件与附件关系同一事务；时间线显示音频播放器/下载，移除录音只软移除该关系并保留历史占位。普通音频附件也可以通过文件入口导入。
- 新增迁移 `0006_m4_audio_duration`（duration_ms，0～300000ms）与 `0007_m4_progress_audio_links`（进展事件媒体关系）；schema_version=8。音频Range读取要求登录、owner及活动关联。
- 离开详情时，有录音/试听/未上传片段会提示；选择离开将释放麦克风并丢弃未提交本机片段。退出账号同样提示。确认提交的捕获媒体通过创建事务关联，进展附件与追加进展同事务。

## 已验证

- `npm run typecheck`、`npm run test:m4`（生产构建、M1～M4隔离回归）、`npx drizzle-kit check`均通过。
- 隔离HTTP/DB集成验证：有效合成WebM容器上传与duration_ms、快速捕获资产随任务创建原子关联且重试不重复、只音频进展提交、进展事件查询返回对应媒体、私有Range读取、进展附件软移除后历史占位保留且文件不再可通过该关系读取。
- 全部迁移0000～0007只在隔离测试库应用；正式数据库未迁移。

## 尚未通过／待现场验证

- 运行环境无目标麦克风，无法真实执行getUserMedia授权/拒绝、MediaRecorder停止最后片段、真实容器解码播放、断网/来电/锁屏中断及真实上传跨设备播放。Q-08格式矩阵仍未由目标手机与桌面浏览器探针锁定；合成WebM接口测试不是硬件证明。
- 录音片段、staged asset IDs不写入M4-03 IndexedDB本机草稿；刷新/退出前会提示，但用户确认离开后片段引用丢失，服务端未关联staging按保留策略后续清理。完整24小时staging清理和媒体备份恢复属于运维/M8范围。
- 媒体文件或附件关联事务失败不会冒充保存成功；实际不同厂商的浏览器MIME、音轨中断及设备切换仍需要逐项记录。

因此 M4-06 仍为进行中，不勾选；需先按 `ACCEPTANCE_M4_01.md` 在真实目标设备执行能力探针和录音闭环，再根据实测补齐格式兼容/问题并更新AT-34结论。
