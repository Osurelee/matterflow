# M4-07 统一捕获与批量预览验收

日期：2026-10-13；状态：已完成（隔离API/DB与生产构建验收）。依据PRD v0.6.2第6.1～6.2节、FR-21/27、AT-35/36与技术设计第3.2、6节。

## 实际交付

- 快速新增保留紧凑标题输入/Enter单件保存；“展开捕获选项”支持正文、图片/文件暂存、页面录音、来源URL及来源名称、空间/项目上下文。
- 单件捕获通过 `POST /api/captures`。仅有媒体且标题为空时生成可改的临时标题（图片记录/语音记录/附件记录＋时间）；正文、来源、媒体assetIds及Task创建/附件关联事务提交。失败保留表单文字和媒体片段/可重试项，不假报成功。
- 图片/文件先在本机预览并逐项上传到私有staging；只有用户创建捕获成功时才关联Task。录音沿用M4-06 staged流程。媒体保留权限和checksum契约；待提交staging不显示为已保存Task附件。
- 多行模式明确要求用户预览后确认；每行可改/移除，最多50条。`POST /api/capture-batches` 将事项与 `capture_batches/capture_batch_items` 记录原子写入；同requestId重复只返回同批结果；任何一行/来源校验失败整批回滚。修改预览内容后使用新requestId，网络重试沿用原requestId。
- 来源链接只接受有效HTTP/HTTPS URL，不抓取网页；单件/批量事项均保存source_url/source_label，在详情中作为可回查链接显示。
- 新增迁移 `0008_m4_unified_capture`（source_url/source_label、批次与批项表）；创建时有正文则保存纯文本派生值与首个正文修订。SCHEMA_VERSION=9。

## 验证结果

- `npm run test:m4`：通过，包括生产构建、M1～M4契约与隔离HTTP/SQLite综合测试。
- `npx drizzle-kit check`：通过。
- 集成覆盖：单次capture带正文/source字段持久化读取、同requestId重放不重复；多行batch创建两个Task/两条批项记录、重放不重复；非法来源导致任务数不变；媒体capture接口与此前M4-05/M4-06媒体链路共用隔离媒体目录。
- 迁移0000～0008在隔离回归库执行；正式数据库未迁移。

## 限制

- 未做目标手机/桌面浏览器手工视觉验收；相机菜单/粘贴及麦克风实测归M7/M4-06探针。
- 多行拆分当前仅承载标题和统一来源字段；媒体暂存时界面提示先切回单件捕获，不将一份附件静默复制到多条事项。
- 媒体staging尚无24小时清理任务，完整媒体备份/恢复属M8；服务端临时asset超期清理不由此项宣称完成。
